# Frontend: generic indicator plugins

Scope: `static/js/app.js` and the plugin modules. The browser draws what the
host relays from indicator libraries; it contains no indicator algorithm and no
branch on an indicator/output id (enforced by `tests/plugin-ui.test.cjs`).

## Modules

| module | role |
|---|---|
| `plugin-wire.mjs` | Only module that knows the host envelopes: `GET /indicators`, `/history` `indicators` block, typed `/ws` frames (`indicator`, `indicator_status`, `indicator_reset`). Errors are reduced to public codes; messages are never shown. |
| `plugin-store.mjs` | Columnar SDK `Output` values keyed by (output, mode, canonical bar time). Base bars are never modified. Live fencing per (indicator, mode): hub generation → runner session → seq. Bounded pending results ahead of the base axis. |
| `plugin-registry.mjs` | Validates SDK descriptors, builds panes/groups/readouts generically; tracks pending (starting/failed/disabled/unavailable) and rejected entries. |
| `plugin-render.mjs` | Renderer adapters by output kind. |
| `segmented-series.mjs` | Generic segmented-line geometry (history custom series + native tail). |
| `legacy-prefs.mjs` | One-time migration of pre-plugin prefs (`showLevels`, `flowMode`) into `plugins.enabled/modes`. The only place naming historical ids. |

## Rendering rules

* Price pane is host-owned (candles + hidden whitespace **backbone** series
  holding every cached timestamp). Backbone never belongs to a plugin; plugin
  data can never extend the time axis.
* `pane: "price"` overlays price; `pane: "separate"` → one pane per
  (indicator, `pane_group` ?? output key), in discovery order.
* Kinds: `line` → 1 native line; `histogram` → 1 native histogram + zero
  line; `dual_range` → separate pane: dual-range histogram around 0 (`upper`,
  `lower` signed); price pane: two band-edge lines; `segmented_lines` → per
  layer ≤ 2 series (one custom history series + one native tail carrying the
  last-value label when `tail_marker`). No per-gap series.
* Two or more bar-type outputs (histogram/dual_range) in one separate pane are
  alternatives → generated mode `<select>`; lines always draw.
* `readout_only` lines are never drawn; they appear in the pane readout (Flow
  `Total` in both modes).
* `colors`: line [stroke]; histogram [up, down]; dual_range [upper, lower];
  segmented one per layer. `widths`: empty = native default (segmented 1),
  one value = whole output, one per layer for segmented.
* Missing value (absent, `null`, non-finite) = whitespace; true zero stays
  zero. Faulted/unavailable/disabled outputs are cleared and labelled.

## Lifecycle

* Discovery at startup; bounded backoff refresh (1–30 s, 6 tries) while any
  indicator is `starting`/`unavailable` or discovery failed, and on live frames
  naming an unknown id. Becoming ready re-registers and refetches the newest
  page with results.
* `/history` results are written per page (generation-fenced with the base
  history request); unavailable modes clear and label.
* `/ws`: typed indicator frames are parsed before base-bar handling; a
  malformed indicator frame triggers a results resync and never closes the
  base feed. `indicator_reset` clears results and refetches; a seq gap
  refetches. Fences reset per connection; results reset on source/tf reload.
* Hidden tab / pagehide: zero native chart writes; one coalesced paint on
  return.

## Tests

```sh
node --test tests/*.test.cjs static/js/*.test.cjs
```

`tests/fixtures/plugin-web.json` is generated by
`cvd-indicators/conformance/src/bin/web-fixture.rs` from REAL public cdylibs
under the REAL runner (do not hand-edit). The browser harness
`tests/browser-interaction.mjs` serves real runner output per page/tick:

```sh
TMPDIR=... CVD_INDICATOR_RUNNER=<runner> CVD_INDICATOR_LIBS=<abs .so list> CVD_REPS=1 node tests/browser-interaction.mjs
```

## Known gaps

* No as-of/revision correlation yet between a live indicator frame and the
  base-bar revision it was computed from (needs a host field); a delayed frame
  for an older forming-bar revision is applied by time.
* `session` / `api_version` on live frames are accepted when absent (treated as
  implicit session 0 / v1) until the host adds them.
